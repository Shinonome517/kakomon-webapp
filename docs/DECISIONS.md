# 設計判断ログ

ユーザー確定事項はSPECのU01〜U12です。以下は未指定部分を埋める設計判断であり、ユーザーの発言として扱わないでください。

| ID | 判断 | 理由 |
|---|---|---|
| D01 | Django 5.2 LTS＋SQLiteを実装基準にする。 | ユーザー名認証・管理CLI・ORM・マイグレーションを小さく構成し、Dockerなしでもローカルテストするため。 |
| D02 | Next.js、Supabase、外部認証は初版で使用しない。 | 以前の候補であり採用は未確定。今回の全データ自宅配置と簡単な認証を優先するため。 |
| D03 | ホストNginx→ループバック公開のアプリコンテナ。 | IPv6/TLS/送信元FWをホストで扱い、Dockerの外部公開ポートを最小化するため。 |
| D04 | 画像は不変ファイル＋DB参照。 | 複数図の再利用、更新、バックアップ整合性を扱いやすくするため。 |
| D05 | 履歴は残し、現在の正答率は最新の有効回答だけ。 | 将来拡張と監査を可能にしつつ、ユーザー指定の集計を守るため。 |
| D06 | 採点版変更後は現在集計で再学習扱い。 | 正解訂正で過去の結果を黙って変えず、不正確な現在成績を避けるため。 |
| D07 | アカウント管理はCLI、管理者用Web画面は作らない。 | 少人数の初版で公開面と実装範囲を小さくするため。 |
| D08 | 夜間は作業ツリー編集とローカル検証のみ、commit/push/deployなし。 | 人間が公開前に内容を確認でき、サンドボックスのGit保護とも整合するため。 |
| D09 | 実問題と個人マニュアルをコードから分離。 | Git公開、データの権利・正確性確認、秘密情報管理を別々に扱うため。 |
| D10 | 1回10問・選択肢順固定・明示的な次へ。 | 電車内で短時間学習でき、解説を読む時間を確保するため。 |
| D11 | リポジトリのソフトウェアはAGPL-3.0-onlyとする。 | ネットワーク経由で提供される改変版についても、利用者が対応ソースを取得できるようにするため。実問題データ・PDF・画像はリポジトリに含めず、このライセンスの対象外とする。 |

## 実装中の追記形式

```text
ID:
日付:
決定:
理由:
検討した代替案:
関連要件／テスト:
未検証事項:
```

個人情報、実環境の接続先、秘密値、内部思考は書かず、必要な結論だけ残してください。
